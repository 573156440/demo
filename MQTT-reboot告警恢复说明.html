MQTT Reboot 后 event-values 告警丢失 — 排查与修复说明

服务器：192.168.2.201　日期：2026-06-12

一、现象

系统 reboot 后，MQTT 上 event-values/# 订阅无消息；MySQL event_value_lasts 中仍有活动告警（phase=start）。

二、根因（两个独立问题）

问题原因影响
Mosquitto persistence 未生效Broker 以 nobody 运行，原路径 /root/app/data/mosquitto/ 因 /root 权限 700 无法写入，日志报 Permission deniedBroker 重启后所有 retained 消息丢失
monitoring 启动不重发monitoring.yaml 中 DisablePublishLast: true，CEP 启动时跳过 PublishLastValues()即使 DB 有告警，也不会补发到 MQTT

三、只改 monitoring 能否解决问题？

能。针对「reboot 后活动告警 event-values 消失」这一问题，仅将 DisablePublishLast 改为 false 即可解决。

原理：monitoring 启动后会从 MySQL 读取 event_value_lasts / signal_value_lasts，并以 retain=true 重新发布到 MQTT。

注意：monitoring 完全启动约需 15～20 秒，此期间前端可能暂时看不到告警，属正常现象。

已在 201 上验证：删除 mosquitto.db、空启动 broker 后，仅重启 monitoring，2 条 event-values 告警均恢复。

四、是否还需要改 Mosquitto？

建议改，但不是解决 event-values 的必要条件。

场景仅 DisablePublishLast=false+ Mosquitto persistence
整机 reboot 后活动告警恢复✅ 可以（等 monitoring 启动）✅ 可以（更快）
仅重启 broker、不重启 monitoring❌ 消息仍丢失✅ 从 mosquitto.db 恢复
signal-values / sample-values 等其它 retained❌ 不自动恢复✅ 持久化保留
MySQL 启动慢于 monitoring⚠️ 可能重发失败✅ persistence 可兜底

五、当前 201 已做修改

1. monitoring.yaml

App:
  DisablePublishLast: false   # 原为 true

2. mosquitto.conf

persistence true
persistence_location /var/lib/mosquitto/   # 原为 /root/app/data/mosquitto/
persistence_file mosquitto.db
autosave_interval 300

3. 目录权限

mkdir -p /var/lib/mosquitto
chown nobody:nogroup /var/lib/mosquitto
chmod 755 /var/lib/mosquitto

六、验证命令

# 订阅活动告警
mosquitto_sub -h 127.0.0.1 -t 'event-values/#' -v -W 5

# 查看 DB 中活动告警
/usr/local/mysql/bin/mysql -uhyiot -phy2022 hussar \
  -e "SELECT equipment, event, JSON_EXTRACT(data,'$.phase') FROM event_value_lasts;"

# 查看 persistence 是否写入
ls -la /var/lib/mosquitto/mosquitto.db

grep -E 'Saving|Permission denied' /root/app/logs/broker.logfile.stdout | tail -5

七、reboot 后预期行为

  1. Broker 先启动（若有 mosquitto.db 则立即恢复 retained）
  2. MySQL 启动后 monitoring 连接 DB（内置重试最多 10 次）
  3. CEP 启动完成 → 从 DB 重发 event-values / signal-values（DisablePublishLast=false）
  4. 约 20 秒内前端告警列表恢复正常
